openEO develops an open application programming interface (API) that connects clients like R, Python and JavaScript to big Earth observation (EO) cloud back-ends in a simple and unified way, so each client can work with every back-end and back-ends can be compared on capacity, cost and results. The openEO API specification, process definitions, client libraries (Python, R, JavaScript, Julia, QGIS plugin) and web editor are open source under Apache 2.0, governed by a Project Steering Committee, and openEO is recognised as an OGC Community Standard.

**Areas:** Company · Earth Observation · Geospatial · Remote Sensing · Cloud Processing · Open Source · API Specification · Data Cubes

## How this profile is made

API Evangelist profiles a company's public API surface the way a developer would find it: the website, developer portal and documentation, the specifications it publishes, its public repositories, and its pricing, status and changelog pages. From that it derives the properties above — contracts split per API, workflows, schemas, collections, governance rules, plans and rate limits — and scores them against the published [Kin Score rubric](https://github.com/api-evangelist/kin-score).

The artifacts are published on [APIs.io](https://apis.io), not in this repository. This repository is the public record for openEO: the place to say something is wrong, missing or out of date, and to ask for a re-score or a removal.
